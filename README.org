* Hammerspoon

This is an indispensable config that is based on the awesome [[https://github.com/agzam/spacehammer][SpaceHammer]].

** Caveats

When git-cloning, clone the submodules with ~git clone --recursive~.

** Keyboard hints (=Cmd-Shift-SPC=) and scrolling (=Cmd-Shift-J=)

=hints.fnl= is a Homerow / Vimium style layer built on the Accessibility API.
=Cmd-Shift-SPC= labels every clickable element on screen: the visible parts of all
windows (covered elements are skipped), panels of menu-bar apps such as the emoji
picker (=Cmd-Ctrl-SPC=), the frontmost app's menu bar and any open menu, status
menu items and a visible Dock. Type a label to act on it:

| Key                  | Action                                                    |
|----------------------+-----------------------------------------------------------|
| label                | click (=AXPress= for buttons, links, menus; else a click) |
| =Shift= + last char  | right click                                               |
| =Cmd= + last char    | Cmd-click, e.g. open a link in a new tab                  |
| =Ctrl= + last char   | double click                                              |
| =Alt= + last char    | move the pointer there without clicking                   |
| =/=                  | switch to the minibuffer search (=Ctrl-Alt-SPC=, below)   |
| =DEL=                | delete the last typed character                           |
| =ESC=, =C-g=, hotkey | cancel; any other key cancels and goes through            |

Synthetic clicks are posted with exactly the intended modifiers (keys still held
from the hotkey are ignored), and the pointer is put back afterwards.
Clicking an element in a background window focuses that window first.

=Cmd-Shift-J= outlines the focused window's scroll areas, largest first:

| Key                       | Action                                   |
|---------------------------+------------------------------------------|
| =h= =j= =k= =l= (held)    | scroll smoothly; hold =Shift= for faster |
| =d= / =u=                 | half a page down / up                    |
| =gg= / =G=                | top / bottom                             |
| =TAB=, =S-TAB=, =1=-=9=   | pick another scroll area                 |
| =ESC=, =C-g=, =q=, hotkey | leave                                    |

Scroll events are posted at the area's location, so the pointer doesn't move.

Limitations: apps that expose little through Accessibility (games, some
cross-platform toolkits) get few or no hints. Electron apps are asked to build
their tree (=AXManualAccessibility=) on first use, so the first invocation there
may miss web content. Context menus opened by a right click can't be hinted;
use the arrow keys or type-ahead there.

** Search (=Ctrl-Alt-SPC=) in the minibuffer, and the echo area

Like [[https://shortcat.app][Shortcat]], =Ctrl-Alt-SPC= searches what you can click by its text.
The query is read in an Emacs style minibuffer (=lib/minibuffer.fnl=) along the
bottom of the screen with vertico/orderless style completion: space-separated
terms match in any order. Candidates are the clickable elements on screen
(annotated with their role and app), the windows, and every enabled menu item of
the frontmost app, closed menus included (=File › Save As…=, annotated with its
shortcut in Emacs notation, e.g. =s-S=). Matches on screen are outlined and the
selection is highlighted.

| Key                                 | Action                                     |
|-------------------------------------+--------------------------------------------|
| =C-n= =C-p=, =TAB= =S-TAB=, arrows  | next / previous candidate                  |
| =C-v= =M-v=                         | a page down / up                           |
| =RET=                               | click, choose the menu item, focus window  |
| =S-RET= =s-RET= =C-RET= =M-RET=     | right click, Cmd-click, double click, move |
| =C-a= =C-e= =C-b= =C-f= =M-b= =M-f= | move point                                 |
| =DEL= =C-d= =M-DEL= =C-w= =M-d=     | delete / kill backward and forward         |
| =C-k= =C-u= =C-y=, =s-v=            | kill line, yank (or paste the clipboard)   |
| =C-g=, =ESC=                        | quit                                       |

The same strip doubles as the echo area: the global =alert= (used throughout this
config) and the hints' messages show there for a few seconds, and are printed to
the Hammerspoon console, which plays the part of =*Messages*=. While the
minibuffer is active, a message appears after the input as =[message]=.

** Keyboard Shortcuts commands (=Cmd-SPC k=)

=Cmd-SPC k= reads any command of System Settings › Keyboard › Keyboard Shortcuts in
the minibuffer (=system-shortcuts.fnl=), annotated with its category and current
shortcut (=(off)= when disabled), plus the frontmost app's Services. =RET= runs it,
whether or not it has a shortcut and whether or not that shortcut is enabled.

The list is read from System Settings' own table
(=/System/Library/ExtensionKit/Extensions/KeyboardSettings.appex=), so it follows
the macOS version and language; only existing desktops are offered for =Switch to
Desktop N=. A command runs by temporarily binding its symbolic hotkey to a spare
chord (Hyper-fn-F19) through the private CGS API, called from JavaScript for
Automation, posting that chord and restoring the original binding 0.25 s later.
This only touches the WindowServer's copy; the preferences are never written, so a
crash in between is undone at the next login. It also works when the system
shortcut collides with a Hammerspoon hotkey, e.g. Spotlight's =Cmd-SPC=.

To bind one directly in =config.fnl=:

#+begin_src fennel
{:key :n :title "Notification Center"
 :action ((. (require :system-shortcuts) :action) "Show Notification Center")}
#+end_src

App Shortcuts are ordinary menu items, which the search (=Ctrl-Alt-SPC=) finds.

** Launcher (=Cmd-SPC SPC=)

=Cmd-SPC SPC= opens the launcher (=launcher.fnl=) in the minibuffer. Its candidates
are the apps (=/Applications=, =/System/Applications=, =~/Applications= and their
subfolders such as Nix Apps), the panes of System Settings, system commands (lock,
sleep, restart, shut down, log out, empty or open the Trash, eject, dark mode, keep
awake, mpv and volume controls, clipboard history), every Keyboard Shortcuts command, and
=Quit=, =Hide= and =Force Quit= for each running app. The ones you pick most often
move to the top. Depending on what you type, it also offers:

| Input                           | Candidate                                          |
|---------------------------------+----------------------------------------------------|
| =2^10/3=, =1.5*(4+2)=           | the result, =RET= copies it                        |
| ~=sqrt(2)*pi~                   | the same with Lua's =math= functions and =e=, =ln= |
| =g nix flakes=                  | a web search by keyword (=web-searches=)           |
| =example.com/path=, =https://…= | open the URL                                       |
| ='name=, =open name=            | Spotlight file search by name                      |
| =find name=                     | the same, revealing the file in Finder             |
| =in text=                       | Spotlight search of file contents                  |
| =$ command=                     | run it in a new Ghostty (or Terminal) window       |
| anything else                   | fallback searches on Google, DuckDuckGo, Wikipedia |

Keywords: =g= Google, =ddg= DuckDuckGo, =wiki= Wikipedia, =yt= YouTube, =gh=
GitHub, =maps= Maps, =nix= Nix packages, =amazon=, =imdb=, =translate= and =define=
(Dictionary). Add your own to =web-searches= in =launcher.fnl=.

| Key            | Action                                               |
|----------------+------------------------------------------------------|
| =RET=          | open / run                                           |
| =s-RET=        | reveal the app or file in Finder                     |
| =M-RET=, =M-w= | copy the result, path, URL or command                |
| =s-l=          | Large Type: the selection (or the input) full screen |
| =s-y=          | Quick Look the file                                  |
| =s-e=          | open the file in Emacs (=emacsclient -n=)            |
| =C-.=          | choose an action for the selection from a list       |

=C-.= lists what applies to the selection: for a file, Open, Open in Emacs, Reveal in
Finder, Copy Path, Copy Name, Quick Look and Large Type; for anything else, Run, Copy
and Large Type.

Restart, shut down, log out, empty the Trash and clearing the clipboard history ask
=y or n= first. To open the launcher with =Opt-SPC= instead, quit the app that holds
that hotkey and add to =agnostic-keys= in =config.fnl=:

#+begin_src fennel
{:mods [:alt] :key :space :action "launcher:show"}
#+end_src

** Clipboard history (=Cmd-SPC y=)

=clipboard.fnl= remembers the last 200 texts you copy (each up to 20,000
characters). Only text is recorded.

| Key   | Action                                     |
|-------+--------------------------------------------|
| =y y= | pick an entry in the minibuffer            |
| =y c= | clear the history (asks first)             |
| =y p= | pause recording                            |
| =y r= | resume recording                           |
| =y Y= | toggle recording                           |

Entries are annotated with the app they were copied in and when. In the minibuffer,
=RET= pastes the entry into the frontmost app, =s-RET= only copies it, =s-l= shows it
in Large Type and =s-DEL= forgets it. The launcher also offers =Clipboard History=,
=Clear Clipboard History…= and =Pause= / =Resume Clipboard History=.

Like Emacs' kill ring, the history lives only in memory: it is never written to
disk (earlier versions kept it in =hs.settings=; that copy is erased on load) and it
is gone when Hammerspoon reloads or quits. To keep secrets out of it, a copy is not
recorded when:

- the app marks it concealed or transient (the [[http://nspasteboard.org][nspasteboard.org]] types);
- a password manager (Passwords, Keychain Access, Proton Pass, 1Password, Bitwarden,
  KeePassXC, …) is the frontmost app;
- it looks like a secret: a GitHub, GitLab, OpenAI/Anthropic, Stripe, Slack, AWS,
  Google or npm token, a JWT, a private key, an assignment such as
  =DB_PASSWORD='…'=, or a single password-like word (letters, digits and symbols
  mixed);
- recording is paused (=Cmd-SPC y p= or =y Y=).

The checks are heuristics. Pause recording before copying a secret that none of them
would catch.

** Windows (=Cmd-SPC w=)

=windows.fnl= arranges the focused window and its neighbours, like Emacs' =C-x 4=
and winner-mode.

| Key             | Action                                                  |
|-----------------+---------------------------------------------------------|
| =h= =j= =k= =l= | focus the window to the left / below / above / right    |
| =C-h= … =C-l=   | move the window (repeatable)                            |
| =s-h= … =s-l=   | move a border (repeatable)                              |
| =H= … =L=       | resize to that half                                     |
| =w=             | the last window                                         |
| =m= / =M=       | maximize / minimize                                     |
| =c=             | center and enlarge                                      |
| =g=             | the grid                                                |
| =d=             | close the window                                        |
| =f=             | toggle full screen                                      |
| ===             | balance: tile the screen's windows                      |
| =v= / =s=       | split side by side / stacked with the last window       |
| =r= / =R=       | rotate the screen's windows forward / back (repeatable) |
| =u= / =U=       | undo / redo the last window change (repeatable)         |

Undo remembers the frames of up to 50 changes, across all the commands above and
restoring a layout; a change that moved several windows undoes in one step.

** Buffers (=Cmd-SPC b=)

=buffers.fnl= treats windows as buffers.

| Key           | Action                                                   |
|---------------+----------------------------------------------------------|
| =b b=         | switch to any window by name, most recently used first   |
| =b n= / =b p= | next / previous window of the frontmost app (repeatable) |
| =b TAB=       | the last window                                          |
| =b d=         | close the window                                         |

The switcher lists windows on every Space, minimized and hidden ones included (it
unminimizes or unhides them), annotated with the app. =s-w= closes the selected
window and reopens the switcher.

** Spaces (=Cmd-SPC t=, =Cmd-SPC [= / =]=)

=spaces.fnl= switches desktops like a tab bar (Emacs' =tab-bar-mode=).

| Key                      | Action                                                 |
|--------------------------+--------------------------------------------------------|
| =t t=                    | pick a Space; annotations list its apps                |
| =t TAB=                  | the last Space                                         |
| =t h= / =t l=, =[= / =]= | the Space to the left / right (repeatable)             |
| =t 1= … =t 9=            | desktop N                                              |
| =t N=                    | new desktop, then switch to it                         |
| =t d=                    | close the current desktop (asks first; never the last) |

Switching uses the system's Switch to Desktop and Move left/right a space shortcuts
(=Keyboard Shortcuts commands=), so it animates as usual. Full-screen apps are
reached through =t t=.

** Layouts (=Cmd-SPC D=)

=layouts.fnl= saves and restores where the windows are, like Emacs' =desktop=
(=SPC D= in =init.el=).

| Key   | Action                                          |
|-------+-------------------------------------------------|
| =D s= | save the layout under a name (overwriting asks) |
| =D r= | restore a layout                                |
| =D d= | delete a layout (asks first)                    |
| =D R= | restore the layout last saved or restored again |

A layout records the visible, standard windows of every Space: app, title, frame
and screen. Restoring matches windows by app and title; windows of the same app
whose titles changed take the remaining frames in order. Apps that aren't running
are skipped, not launched, and the echo area counts the windows that weren't open.
A layout saved on a screen that is gone is scaled onto the main screen. Layouts are
kept in =hs.settings=; =Cmd-SPC w u= undoes a restore.

** Quit (=Cmd-SPC q=)

| Key   | Action                                                             |
|-------+--------------------------------------------------------------------|
| =q q= | quit the frontmost app, as =Cmd-Q= does (it may still ask to save) |
| =q Q= | force quit it; unsaved changes are lost                            |
| =q r= | relaunch it (Hammerspoon itself reloads)                           |
| =q f= | close the window                                                   |

Each asks =y or n= first (=quit.fnl=).

** Embark (=Cmd-SPC e e=)

=embark.fnl= acts on the selected text, like Emacs' =embark-act=. The text is the
accessibility selection, else what =Cmd-C= copies (the clipboard and its history
are left as they were), else the clipboard. The actions offered depend on it:

- a file or folder path: Open, Reveal in Finder, Open in Emacs;
- a URL: Open URL;
- arithmetic: Copy Result;
- always: the launcher's web searches, Copy, Large Type, Count Words, Edit in Emacs
  (a new =*selection*= buffer) and Ask ChatGPT (pasted into the composer as a draft,
  not sent).

** Toggles (=Cmd-SPC T=)

=toggles.fnl= flips system settings, like Spacemacs' =SPC t=; the echo area shows
the new state.

| Key   | Toggle                                            |
|-------+---------------------------------------------------|
| =T F= | full screen                                       |
| =T t= | dark mode                                         |
| =T d= | Dock hiding                                       |
| =T m= | menu bar hiding                                   |
| =T h= | hidden files in Finder (asks, as Finder restarts) |
| =T n= | Do Not Disturb                                    |
| =T a= | keep awake (prevents idle sleep)                  |
| =T v= | output mute                                       |
| =T w= | Wi-Fi (asks before turning it off)                |
| =T b= | Bluetooth (asks before turning it off)            |

Bluetooth uses =blueutil=, which needs Hammerspoon to be allowed to use Bluetooth
(System Settings › Privacy & Security › Bluetooth); until then the toggle says so
and opens that pane.

** Eval (=Cmd-SPC :=)

=eval.fnl= evaluates a Fennel expression in Hammerspoon, like Emacs' =M-:=. Short
values go to the echo area, long ones to the help HUD; errors are echoed, with the
traceback in the console. Earlier expressions are offered as candidates, and =RET=
with an empty input evaluates the selected one again.

** System (=Cmd-SPC A=)

| Key   | Action                                                                 |
|-------+------------------------------------------------------------------------|
| =A i= | macOS, host, CPU, memory, uptime, load, power, disks and network       |
| =A c= | world clock for the cities of =elispm/world-clock-cities= in =init.el= |
| =A p= | your processes, by CPU use: =RET= terminates one, =s-k= force quits it |

Both process actions ask =y or n= first and name the process and its PID
(=sysinfo.fnl=).

** Media (=Cmd-SPC p=)

=mpv.fnl= controls mpv through its JSON IPC socket: the one given with
=--input-ipc-server= (as EMMS does), else =$TMPDIR/mpv-<pid>.sock=, which the mpv
script =mpv-scripts/ipc-socket.lua= opens in every other mpv and removes on quit.
Home Manager links that script to =~/.config/mpv/scripts/=; without it, only mpv
started with =--input-ipc-server= is found. The echo area shows the result; seeking shows the new position, or updates the HUD if it is open.

| Key           | Action                                                    |
|---------------+-----------------------------------------------------------|
| =s=           | play or pause                                             |
| =h= / =l=     | previous / next track (repeatable), then show Now Playing |
| =,= / =.=     | seek back / forward 10 seconds (repeatable)               |
| =<= / =>=     | seek back / forward 1 minute (repeatable)                 |
| =j= / =k=     | mpv's volume down / up by 5 (repeatable)                  |
| =m=           | mute or unmute mpv                                        |
| =n=           | show or hide the Now Playing HUD                          |
| =a=           | open EMMS's playlist in an Emacs frame named =EMMS=       |
| =r=           | play an internet radio station                            |
| =R=           | stop the radio                                            |

When several mpv instances are running, the keys control the one that is playing,
else the one controlled last, else the newest. For the mpv that EMMS started, play,
pause and tracks go through EMMS (=emms-pause=, =emms-next=, =emms-previous=), so
its playlist and paused state stay in sync; volume and mute go to mpv directly. The
launcher's =Play/Pause=, =Next Track=, =Previous Track= and =Now Playing= do the
same, while its =Mute= and =Volume= commands still change the system volume.

The radio (=radio.fnl=) plays Emacs' =eradio-channels= in its own background mpv
(socket =$TMPDIR/mpv-radio.sock=), so the keys above control it while it plays, and
picking another station reuses it. The stations are read from Emacs when it is
running and cached; otherwise a few defaults are offered.

The Now Playing HUD (=now-playing.fnl=) shows the album art, title, artist, album,
position and a progress bar in the top-right corner. It updates every second, hides
after 8 seconds, and lets clicks through. The art is the file's embedded cover
(extracted with ffmpeg), else an image in its folder named =cover=, =folder= or
=front=, or the folder's only image if it holds an album (two or more tracks), cached as a PNG in the temporary directory. The files are read by a
background process, so Hammerspoon never waits on them; music on an external drive
needs Hammerspoon to be allowed to access removable volumes (System Settings ›
Privacy & Security › Files and Folders).

** Help (=Cmd-SPC h=)

=describe.fnl= mirrors Emacs' =C-h= commands. Short answers go to the echo area; long
ones open a less-like help HUD (=lib/help.fnl=).

| Key | Command            | Describes                                                          |
|-----+--------------------+--------------------------------------------------------------------|
| =k= | describe-key       | What the next chord (or leader sequence) runs, and what it shadows |
| =b= | describe-bindings  | Every binding active in the frontmost app                          |
| =w= | where-is           | Pick a command in the minibuffer and show its keys                 |
| =f= | describe-function  | Pick a command or Hammerspoon API function: docs, keys and source  |
| =a= | apropos-command    | Commands whose name, title or docs contain all the words you type  |
| =e= | =*Messages*=       | Echo-area messages and errors since the last config reload         |
| =.= | describe-element   | The focused accessibility element                                  |
| =p= | element at pointer | The accessibility element under the mouse pointer                  |
| ~=~ | describe-char      | The character at point, or each character of the selection         |
| =m= | describe-mode      | The frontmost app's mode keymap                                    |
| =A= | describe-app       | The frontmost app: bundle, process, mode, windows, key counts      |
| =W= | describe-window    | The focused window: frame, screen, Space and state                 |

describe-function lists Fennel functions with docstrings, launcher commands and the
Hammerspoon API (=hs.doc=); =s= in the HUD visits the source. describe-char reads the
focused text field through accessibility, so it works in native text views and most
browser fields. =*Messages*= reads the Hammerspoon console, which is cleared on every
config reload.

Bindings are collected from several layers. When a chord is bound in more than one,
the first one wins and describe-key lists the rest as shadowed:

1. Hammerspoon: global keys, app keys, the leader menu (including the app's mode) and
   any other hotkey. =lib/hotkeys.fnl= records every =hs.hotkey= with its call site,
   and Fennel docstrings are kept at runtime (=useMetadata=).
2. macOS: System Settings › Keyboard Shortcuts.
3. The frontmost app's menus. Reading them takes a second or two in large apps.

describe-key swallows the chord it reads, so nothing runs; =C-g= quits. After
=Cmd-SPC= it keeps reading keys until it reaches a command, like =C-h k= on a prefix.

Help HUD keys:

| Key                                     | Action                                                  |
|-----------------------------------------+---------------------------------------------------------|
| =j= / =k=, =C-n= / =C-p=, arrows, =RET= | Scroll a line                                           |
| =SPC=, =f=, =C-v= / =b=, =DEL=, =M-v=   | Page down / up                                          |
| =d= / =u=                               | Half page down / up                                     |
| =g=, =<=, =M-<= / =G=, =>=, =M->=       | Top / bottom                                            |
| =/=, =n=, =N=                           | Search, next, previous                                  |
| =s=                                     | Visit the source in Emacs (=emacsclient=)               |
| =o=                                     | Open the text in an Emacs buffer (=*Hammerspoon Help*=) |
| =M-w=                                   | Copy the text                                           |
| =?=                                     | Key summary                                             |
| =q=, =Esc=, =C-g=                       | Quit                                                    |

Cmd chords close the HUD and pass through to the app.

** Application modes (=Cmd-SPC m=, =Cmd-Shift-,=)

Like Emacs major modes, the frontmost application selects a local keymap. =Cmd-SPC m=
resolves the frontmost app once (by bundle id) and opens its keymap in the regular
leader menu, so the which-key style popup, =C-g= (back) and =Esc= (cancel) behave as
everywhere else. Media moved from =Cmd-SPC m= to =Cmd-SPC p=.

=Cmd-Shift-,= is the Spacemacs-style local leader: it opens the mode keymap
directly, exactly as =Cmd-SPC m= does, so =Cmd-Shift-, b n= is =Cmd-SPC m b n=.

** Which-key panel

Leader menus are drawn by =lib/which-key.fnl= as an Emacs which-key style panel along
the bottom of the screen with the focused window. Entries are sorted (commands first,
then =+prefix= groups) and laid out column by column, at least six rows high. Keys use
Emacs notation: =s-h= is Cmd-h, =H= is Shift-h, =SPC= is space. Mode commands show
their registry id, e.g. =finder.view.list=. The bottom echo line shows the key path
and keymap, e.g. =SPC m v- finder-mode › view=.

Menu items marked =:repeatable true= (e.g. the =SPC w= move/resize keys) keep the menu
open and auto-repeat while held, at the system key-repeat rate. The menu closes after
2 seconds without a repeatable key press.

| =safari-mode=   | see below | =safari.*=                 | Safari menu items (table below)             |
| =chatgpt-mode=  | =i=     | =chatgpt.focus-input=        | Same as =Ctrl-l= (accessibility focus)      |

Behaviour:
- An app without a mode shows "No mode for …" and binds nothing.
- An undefined key cancels the sequence and is swallowed (not typed into the app).
  Cmd chords such as =Cmd-,= cancel and pass through to the app.
- Switching applications cancels an open mode keymap.
- =C-g= goes back one level, and closes the leader at the top level, as in Emacs.
  =Esc= and =C-[= close it from any level. =SPC= is not bound in menus; in a mode
  keymap it is an undefined key like any other.
- Like Emacs prefixes, there is no idle timeout.
- Menu commands rely on the app's reported menu state, which can be stale for
  about 0.5 s after the app becomes frontmost. A command fired in that window
  may show "Unavailable now".

*** Adding a mode

1. Write the commands, e.g. =podcasts.fnl= returning ={:commands {...}}=. Each
   command is ={:title "..." :fn (fn [app] ...)}= and receives the app resolved
   when the leader was entered. =lib.modes= provides =menu-item= (select a menu
   path; an element may be a list of alternative titles, e.g.
   =["View" ["Show Sidebar" "Hide Sidebar"]]=, for items renamed by state), =menu-item-matching= (select a menu item by Lua
   pattern, for titles that embed the selection such as Copy “a.txt” as Pathname)
   and =press-button= (AXPress a button in the focused window).
2. Declare the mode in =config.fnl= and add it to =:modes=:

#+begin_src fennel
(local podcasts-mode
       {:id :podcasts-mode
        :title :Podcasts
        :bundle-ids [:com.apple.podcasts]
        :commands (. (require :podcasts) :commands)
        :keymap [{:key :p :title :play :command :podcasts.play-pause}
                 {:key :g :title :go          ; prefix: any depth of :items
                  :items [{:key :l :title :library :command :podcasts.library}]}]})
#+end_src

The keymap is the single source of truth for dispatch and help. Commands can be
run without their key sequence, and both can be introspected from the console:

#+begin_src lua
modes = require("lib.modes")
modes["execute-command"]("safari.toolbar.customize")
print(modes["describe-mode"]("safari-mode"))
print(hs.inspect(modes["describe-key"]("safari-mode", {"t", "s"})))
print(hs.inspect(modes["list-commands"]()))
#+end_src
