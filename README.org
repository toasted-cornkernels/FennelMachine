* Hammerspoon

This is an indispensable config that is based on the awesome [[https://github.com/agzam/spacehammer][SpaceHammer]].

** Caveats

When git-cloning, clone the submodules with ~git clone --recursive~.

Everything that talks to Emacs (EMMS play/pause/tracks, the radio's stations, Emacs
mode commands, capture, "Open in Emacs") uses =emacsclient=, so Emacs must be running
its server; ELispMachine's =init.el= starts it. If it isn't, those keys say
"Emacs isn't running its server: M-x server-start" in the echo area.

** Keyboard hints and scrolling (=Cmd-Shift-SPC=, then =TAB=)

=hints.fnl= is a Homerow / Vimium style layer built on the Accessibility API.
=Cmd-Shift-SPC= labels every clickable element on screen: the visible parts of all
windows (covered elements are skipped; a partly covered one is labelled and
clicked on its visible part, which must be at least 8px each way, and a window
in front also covers the 4px margin around it where a click would resize it;
rows scrolled under a list's column header count as covered too), notification
banners and alerts, panels of menu-bar apps such as
the emoji picker (=Cmd-Ctrl-SPC=), the frontmost app's menu bar and any open menu,
status menu items and a visible Dock. Clickable text such as Calendar events is
included. Transparent overlay windows, like the full-screen one Notification
Center puts up while an alert is showing, only hide what they actually paint.
Type a label to act on it:

| Key                      | Action                                                    |
|--------------------------+-----------------------------------------------------------|
| label                    | click (=AXPress= for buttons, links, menus; else a click) |
| modifiers + last char    | click with those modifiers held, e.g. =Cmd= opens a link  |
|                          | in a new tab, =Cmd-Shift= in a new front tab              |
| =r= before the last char | right click                                               |
| =t= before the last char | double click                                              |
| =h= before the last char | hover: move the pointer there without clicking            |
| =H= before the last char | press and hold (0.5s), e.g. Safari's speaker button menu  |
|                          | with "Enter Picture in Picture"                           |
| =g= before the last char | drag: pick what, then where to (a second label); its last |
|                          | char's modifiers are held, e.g. =Alt= to copy a file      |
| =y= before the last char | copy text: labels go over text, a line at a time on web   |
|                          | pages; pick where it starts, then where it ends           |
| =v=, then a label        | caret mode: a cursor at the start of that web text line   |
| =Shift-P=                | park: labels turn peach and stay after each action (e.g.  |
|                          | =Cmd= + labels to select several files); =Shift-P= leaves |
| =/=                      | switch to the minibuffer search (=Ctrl-Alt-SPC=, below)   |
| =TAB=                    | switch to scroll mode (below); =TAB= there switches back  |
| =?=                      | show or hide the bindings HUD (in scroll mode too)        |
| =DEL=                    | delete the last typed character, or the first pick        |
| =x=                      | clear the text selected in web pages on screen and in the |
|                          | focused text field                                        |
| =ESC=, =C-g=, hotkey     | cancel; any other key cancels and goes through            |

The action keys combine with modifiers (=r= then =Cmd= + the last char is a
Cmd right click); typing one again goes back to a plain click. While one is
pending, the labels and the HUD title take its colour: sky blue for right click,
green for double click, pink for hold, yellow for hover, blue for drag and red
for copy. At the start of
a label, a modified key bound as a Hammerspoon hotkey, e.g. =Ctrl-Alt-SPC=,
closes the hints and goes through; past the start, a modified label character
is part of the label.

While hints are shown, a small HUD in the bottom right corner of the main screen
lists these bindings; its title names the chosen action and turns peach while
parked. Labels are drawn over it, so elements behind it can still be picked.
Once hidden with =?=, it stays hidden until =?= shows it again. It and the
other overlays at the bottom (which-key, the minibuffer) draw over the Dock.

=g= and =y= take two picks; the first stays outlined until the second, and
picking the same label twice copies just that text. A drag also labels text and
images, which may be draggable or drop zones (HTML5 drag and drop works), and
named lists, such as the days of Calendar's month view (labelled and dropped on
along their bottom, below their events, so an event can be moved to another
day), and
leaves the windows where they are. Selected web text (e.g. by =y=) can be dragged
too; web text that can't be dragged gets selected instead, and stays selected,
e.g. for =Cmd-c=. Copying selects web text in the page (via
text markers), focusing it, so =Shift= with the arrow keys can extend the
selection before copying again; other text (labels, text fields) is copied whole,
every labelled text from the first pick through the second joined by newlines.

=v= starts caret mode, after Vimium's: the labels go over web text a line
at a time, and picking one puts a block cursor (rosewater, outlined) at its
start. =h=/=l= move it a character, =j=/=k= a line on screen, wrapped or not,
keeping to its column, and =0=/=$= to the line's start and end; line breaks
and the gaps between blocks are skipped. Vim's other motions work too:

- =w=, =b=, =e= and =ge= by words, telling keywords, punctuation and scripts
  (kanji, kana, hangul) apart as Vim does, and =W=, =B=, =E= and =gE= by words
  between blanks;
- =)= and =(= to the next and previous sentence;
- =}= and ={= to the end and start of the paragraph (a block on the page: a
  paragraph, heading or list item), or of the next or previous one when
  already there, since the cursor cannot rest on the gaps between blocks
  that Vim's would go to;
- =]]= and =[[= to the next and previous heading, and =][= and =[]= to the end
  of the section (from a heading to the next) and of the previous one; the
  page's end or start when there are no more. A key after =g=, =[= or =]= that
  makes no motion cancels it.

=C-e= and =C-y= scroll the page a line down and up, and =C-f= and =C-b= a page
(less two lines), the cursor moving only to stay a few lines from the edge;
=C-d= and =C-u= scroll half a page, the cursor
going as far, so that it stays where it shows; a selection can thus grow past
what is on screen.

The page scrolls to keep a few lines around the cursor in view, and the cursor
follows the page when it is scrolled otherwise. =?= hides the HUD; =ESC=, =C-g= or =q= leaves, and any other key
leaves and goes through. Only web pages (text markers) are supported so far,
in WebKit (Safari) and Chromium (Chrome, Electron apps).

Visual selection works as in Vim: =v= selects from the character under the
cursor and =V= whole lines (lines on screen, as =j=/=k= move), and the moves
above extend it. =v= and =V= switch between the two, or stop selecting when
pressed again; =o= jumps to the other end, =y= copies the selection, stops
selecting and puts the cursor at its start, and =ESC= stops selecting without
leaving. Leaving with =C-g=, =q= or a key that goes through (e.g. =Cmd-C=)
keeps the selection.

Chromium-based apps (Chrome, Electron apps such as ChatGPT) work too, with some
differences, as their accessibility API cannot set the page's selection and
numbers text in pieces that change as the page redraws. The selection is drawn
over the page instead, so =y= or =Cmd-C= copies it (and leaves); the =y= hint
action copies without selecting, and =x= cannot clear their selections. The cursor is found again where it last showed
when the text under it is redrawn. Sentences and paragraphs ignore where lines
wrap and inline elements (e.g. code spans) start and end, which Chromium splits
them at. Headings shown only to screen readers are skipped, and in chats, the
end of the page is the end of the conversation, before the composer, and the
page scrolls to keep the cursor clear of the composer floating over it.

When a full screen app hides the menu bar, its status items are labelled where
they show once it comes back; picking one presses it through Accessibility,
which brings the bar back and opens the item.

Synthetic clicks are posted with exactly the intended modifiers (keys still held
from the hotkey are ignored), and the pointer is put back afterwards.
Clicking an element in a background window focuses that window first.

=TAB= in hint mode switches to scroll mode, which labels every visible scroll
area on screen, in panels and in all windows, so a panel of a background window
can be scrolled without focusing it. The focused window's largest area is
selected first.

| Key                       | Action                                   |
|---------------------------+------------------------------------------|
| an area's label           | select that area                         |
| =h= =j= =k= =l= (held)    | scroll smoothly; hold =Shift= for faster |
| =d= / =u=                 | half a page down / up                    |
| =gg= / =G=                | top / bottom                             |
| =TAB=                     | back to hint mode                        |
| =?=                       | show or hide the bindings HUD            |
| =DEL=                     | delete a typed label key                 |
| =ESC=, =C-g=, =q=         | leave                                    |

Labels leave out the scroll keys, and a HUD in the bottom right lists the
bindings. A window exposing no scroll areas (some Electron apps) is scrolled as
a whole. Browsers report CSS-scrolled panels, such as a web app's sidebar, as
plain groups, so in web content ARIA landmarks (main, navigation,
complementary) and elements whose class names say they scroll (Tailwind's
=overflow-y-auto= and the like) count as areas too. They count only if they fit
inside the page: a section taller than the view scrolls with the page. Of
nested areas, the outer is dropped when its center lies in the inner. Scroll
events are posted at the area's center, so the pointer doesn't move.

Limitations: apps that expose little through Accessibility (games, some
cross-platform toolkits) get few or no hints. Browsers and Electron apps build
their web accessibility tree only once it is first asked for, so every app with
a visible window is asked (Electron via =AXManualAccessibility=; Chromium apps
that ignore it, such as ChatGPT, via =AXEnhancedUserInterface=, which can make
their window move and resize animations choppy). On the first invocation in a
freshly launched app, web hints appear a moment after the rest; labels are
refreshed until every such app's page settles (at most 5 seconds). If a scan
runs out of its time or element budget, the menu bar and Dock lose hints first
and a warning is logged to the Hammerspoon console. Context menus opened by a
right click can't be hinted; use the arrow keys or type-ahead there.

** Search (=Ctrl-Alt-SPC=) in the minibuffer, and the echo area

Like [[https://shortcat.app][Shortcat]], =Ctrl-Alt-SPC= searches what you can click by its text.
The query is read in an Emacs style minibuffer (=lib/minibuffer.fnl=) along the
bottom of the screen with vertico/orderless style completion: space-separated
terms match in any order. Candidates are the clickable elements on screen
(annotated with their role and app), the windows, and every enabled menu item of
the frontmost app, closed menus included (=File › Save As…=, annotated with its
shortcut in Emacs notation, e.g. =s-S=). Matches on screen are outlined and the
selection is highlighted.

| Key                                 | Action                                     |
|-------------------------------------+--------------------------------------------|
| =C-n= =C-p=, =TAB= =S-TAB=, arrows  | next / previous candidate                  |
| =C-v= =M-v=                         | a page down / up                           |
| =RET=                               | click, choose the menu item, focus window  |
| =S-RET= =s-RET= =C-RET= =M-RET=     | right click, Cmd-click, double click, move |
| =C-a= =C-e= =C-b= =C-f= =M-b= =M-f= | move point                                 |
| =DEL= =C-d= =M-DEL= =C-w= =M-d=     | delete / kill backward and forward         |
| =C-k= =C-u= =C-y=, =s-v=            | kill line, yank (or paste the clipboard)   |
| =C-g=, =ESC=                        | quit                                       |

The same strip doubles as the echo area: the global =alert= (used throughout this
config) and the hints' messages show there for a few seconds, and are printed to
the Hammerspoon console, which plays the part of =*Messages*=. While the
minibuffer is active, a message appears after the input as =[message]=.

** Keyboard Shortcuts commands (=Cmd-SPC k=)

=Cmd-SPC k= reads any command of System Settings › Keyboard › Keyboard Shortcuts in
the minibuffer (=system-shortcuts.fnl=), annotated with its category and current
shortcut (=(off)= when disabled), plus the frontmost app's Services. =RET= runs it,
whether or not it has a shortcut and whether or not that shortcut is enabled.

The list is read from System Settings' own table
(=/System/Library/ExtensionKit/Extensions/KeyboardSettings.appex=), so it follows
the macOS version and language; only existing desktops are offered for =Switch to
Desktop N=. A command runs by temporarily binding its symbolic hotkey to a spare
chord (Hyper-fn-F19) through the private CGS API, called from JavaScript for
Automation, posting that chord and restoring the original binding 0.25 s later.
This only touches the WindowServer's copy; the preferences are never written, so a
crash in between is undone at the next login. It also works when the system
shortcut collides with a Hammerspoon hotkey, e.g. Spotlight's =Cmd-SPC=.

To bind one directly in =config.fnl=:

#+begin_src fennel
{:key :n :title "Notification Center"
 :action ((. (require :system-shortcuts) :action) "Show Notification Center")}
#+end_src

App Shortcuts are ordinary menu items, which the search (=Ctrl-Alt-SPC=) finds.

** Launcher (=Cmd-SPC SPC=)

=Cmd-SPC SPC= opens the launcher (=launcher.fnl=) in the minibuffer. Its candidates
are the apps (=/Applications=, =/System/Applications=, =~/Applications= and their
subfolders such as Nix Apps), the panes of System Settings, system commands (lock,
sleep, restart, shut down, log out, empty or open the Trash, eject, dark mode, keep
awake, media and volume controls, opening mpv, clipboard history, converting a time
between time zones), every Keyboard Shortcuts command, and
=Quit=, =Hide= and =Force Quit= for each running app. The ones you pick most often
move to the top. Depending on what you type, it also offers:

| Input                           | Candidate                                          |
|---------------------------------+----------------------------------------------------|
| =2^10/3=, =1.5*(4+2)=           | the result, =RET= copies it                        |
| ~=sqrt(2)*pi~                   | the same with Lua's =math= functions and =e=, =ln= |
| =g nix flakes=                  | a web search by keyword (=web-searches=)           |
| =example.com/path=, =https://…= | open the URL                                       |
| ='name=, =open name=            | Spotlight file search by name                      |
| =find name=                     | the same, revealing the file in Finder             |
| =in text=                       | Spotlight search of file contents                  |
| =$ command=                     | run it in a new Ghostty (or Terminal) window       |
| anything else                   | fallback searches on Google, DuckDuckGo, Wikipedia |

Keywords: =g= Google, =ddg= DuckDuckGo, =wiki= Wikipedia, =yt= YouTube, =gh=
GitHub, =maps= Maps, =nix= Nix packages, =amazon=, =imdb=, =translate= and =define=
(Dictionary). Add your own to =web-searches= in =launcher.fnl=.

| Key            | Action                                               |
|----------------+------------------------------------------------------|
| =RET=          | open / run                                           |
| =s-RET=        | reveal the app or file in Finder                     |
| =M-RET=, =M-w= | copy the result, path, URL or command                |
| =s-l=          | Large Type: the selection (or the input) full screen |
| =s-y=          | Quick Look the file                                  |
| =s-e=          | open the file in Emacs (=emacsclient -n=)            |
| =C-.=          | choose an action for the selection from a list       |

=C-.= lists what applies to the selection: for a file, Open, Open in Emacs, Reveal in
Finder, Copy Path, Copy Name, Quick Look and Large Type; for anything else, Run, Copy
and Large Type.

Restart, shut down, log out, empty the Trash and clearing the clipboard history ask
=y or n= first. To open the launcher with =Opt-SPC= instead, quit the app that holds
that hotkey and add to =agnostic-keys= in =config.fnl=:

#+begin_src fennel
{:mods [:alt] :key :space :action "launcher:show"}
#+end_src

** Clipboard history (=Cmd-SPC y=)

=clipboard.fnl= remembers the last 200 texts you copy (each up to 20,000
characters). Only text is recorded.

| Key   | Action                                     |
|-------+--------------------------------------------|
| =y y= | pick an entry in the minibuffer            |
| =y c= | clear the history (asks first)             |
| =y p= | pause recording                            |
| =y r= | resume recording                           |
| =y Y= | toggle recording                           |

Entries are annotated with the app they were copied in and when. In the minibuffer,
=RET= pastes the entry into the frontmost app, =s-RET= only copies it, =s-l= shows it
in Large Type and =s-DEL= forgets it. The launcher also offers =Clipboard History=,
=Clear Clipboard History…= and =Pause= / =Resume Clipboard History=.

Like Emacs' kill ring, the history lives only in memory: it is never written to
disk (earlier versions kept it in =hs.settings=; that copy is erased on load) and it
is gone when Hammerspoon reloads or quits. To keep secrets out of it, a copy is not
recorded when:

- the app marks it concealed or transient (the [[http://nspasteboard.org][nspasteboard.org]] types);
- a password manager (Passwords, Keychain Access, Proton Pass, 1Password, Bitwarden,
  KeePassXC, …) is the frontmost app;
- it looks like a secret: a GitHub, GitLab, OpenAI/Anthropic, Stripe, Slack, AWS,
  Google or npm token, a JWT, a private key, an assignment such as
  =DB_PASSWORD='…'=, or a single password-like word (letters, digits and symbols
  mixed);
- recording is paused (=Cmd-SPC y p= or =y Y=).

The checks are heuristics. Pause recording before copying a secret that none of them
would catch.

** Windows (=Cmd-SPC w=)

=windows.fnl= arranges the focused window and its neighbours, like Emacs' =C-x 4=
and winner-mode.

| Key             | Action                                                  |
|-----------------+---------------------------------------------------------|
| =h= =j= =k= =l= | focus the window to the left / below / above / right    |
| =s-h= … =s-l=   | drag the left / top border that way (repeatable)        |
| =C-h= … =C-l=   | drag the right / bottom border that way (repeatable)    |
| =M-h= … =M-l=   | move the window (repeatable)                            |
| =H= … =L=       | resize to that half                                     |
| =w=             | the last window                                         |
| =m= / =M=       | maximize / minimize                                     |
| =c=             | center and enlarge                                      |
| =g=             | the grid                                                |
| =d=             | close the window                                        |
| =f=             | toggle full screen                                      |
| ===             | balance: tile the screen's windows                      |
| =v= / =s=       | split side by side / stacked with the last window       |
| =r= / =R=       | rotate the screen's windows forward / back (repeatable) |
| =u= / =U=       | undo / redo the last window change (repeatable)         |

Undo remembers the frames of up to 50 changes, across all the commands above and
restoring a layout; a change that moved several windows undoes in one step.

** Buffers (=Cmd-SPC b=)

=buffers.fnl= treats windows as buffers.

| Key           | Action                                                   |
|---------------+----------------------------------------------------------|
| =b b=         | switch to any window by name, most recently used first   |
| =b n= / =b p= | next / previous window of the frontmost app (repeatable) |
| =b TAB=       | the last window                                          |
| =b d=         | close the window                                         |

The switcher lists windows on every Space, minimized and hidden ones included (it
unminimizes or unhides them), annotated with the app. =s-w= closes the selected
window and reopens the switcher.

** Spaces (=Cmd-SPC t=, =Cmd-SPC [= / =]=)

=spaces.fnl= switches desktops like a tab bar (Emacs' =tab-bar-mode=).

| Key                      | Action                                                     |
|--------------------------+------------------------------------------------------------|
| =t t=                    | pick a Space, most recent first; annotations list its apps |
| =t TAB=                  | the last Space                                             |
| =t h= / =t l=, =[= / =]= | the Space to the left / right (repeatable)                 |
| =t 1= … =t 9=            | the Nth Space, full-screen apps included                   |
| =t N=                    | new desktop, then switch to it                             |
| =t d=                    | close the current desktop (asks first; never the last)     |

Spaces are numbered as Mission Control orders them, like tab-bar's tabs: with
Desktop 1 and a full-screen app, =t 2= is the app. Switching uses the system's
Switch to Desktop and Move left/right a space shortcuts (=Keyboard Shortcuts
commands=), or focuses a full-screen app's window, so it slides as usual; Mission
Control is the fallback.

** Layouts (=Cmd-SPC D=)

=layouts.fnl= saves and restores where the windows are, like Emacs' =desktop=
(=SPC D= in =init.el=).

| Key   | Action                                          |
|-------+-------------------------------------------------|
| =D s= | save the layout under a name (overwriting asks) |
| =D r= | restore a layout                                |
| =D d= | delete a layout (asks first)                    |
| =D R= | restore the layout last saved or restored again |

A layout records the visible, standard windows of every Space: app, title, frame
and screen. Restoring matches windows by app and title; windows of the same app
whose titles changed take the remaining frames in order. Apps that aren't running
are skipped, not launched, and the echo area counts the windows that weren't open.
A layout saved on a screen that is gone is scaled onto the main screen. Layouts are
kept in =hs.settings=; =Cmd-SPC w u= undoes a restore.

** Quit (=Cmd-SPC q=)

| Key   | Action                                                             |
|-------+--------------------------------------------------------------------|
| =q q= | quit the frontmost app, as =Cmd-Q= does (it may still ask to save) |
| =q Q= | force quit it; unsaved changes are lost                            |
| =q r= | relaunch it (Hammerspoon itself reloads)                           |
| =q f= | close the window                                                   |

Each asks =y or n= first (=quit.fnl=).

** Embark (=Cmd-SPC e e=)

=embark.fnl= acts on the selected text, like Emacs' =embark-act=. The text is the
accessibility selection, else what =Cmd-C= copies (the clipboard and its history
are left as they were), else the clipboard. The actions offered depend on it:

- a file or folder path: Open, Reveal in Finder, Open in Emacs;
- a URL: Open URL;
- arithmetic: Copy Result;
- always: the launcher's web searches, Copy, Large Type, Count Words, Edit in Emacs
  (a new =*selection*= buffer) and Ask ChatGPT (pasted into the composer as a draft,
  not sent).

** Toggles (=Cmd-SPC T=)

=toggles.fnl= flips system settings, like Spacemacs' =SPC t=; the echo area shows
the new state.

| Key   | Toggle                                            |
|-------+---------------------------------------------------|
| =T F= | full screen                                       |
| =T t= | dark mode                                         |
| =T d= | Dock hiding                                       |
| =T m= | menu bar hiding                                   |
| =T h= | hidden files in Finder (asks, as Finder restarts) |
| =T n= | Do Not Disturb                                    |
| =T a= | keep awake (prevents idle sleep)                  |
| =T v= | output mute                                       |
| =T w= | Wi-Fi (asks before turning it off)                |
| =T b= | Bluetooth (asks before turning it off)            |

Bluetooth uses =blueutil=, which needs Hammerspoon to be allowed to use Bluetooth
(System Settings › Privacy & Security › Bluetooth); until then the toggle says so
and opens that pane.

** Eval (=Cmd-SPC :=)

=eval.fnl= evaluates a Fennel expression in Hammerspoon, like Emacs' =M-:=. Short
values go to the echo area, long ones to the help HUD; errors are echoed, with the
traceback in the console. Earlier expressions are offered as candidates, and =RET=
with an empty input evaluates the selected one again.

** REPL (Emacs' =fennel-mode=)

=bin/hs-fennel-repl= gives a Fennel REPL inside Hammerspoon on stdin and stdout, so
an editor can run it as its Fennel program. It asks Hammerspoon (=hs -c=, so
=hs.ipc= must be loaded and the =hs= command installed) to open a Unix socket in
=$TMPDIR= for it (=repl.fnl=), and relays to the socket with =nc=. The REPL is
Fennel's own, run in a coroutine, so Hammerspoon carries on while it waits.

In Emacs, the Fennel files of this config set =fennel-program= to the script and
turn on =fennel-proto-repl-minor-mode= (=init.el=), so evaluation, completion,
eldoc, documentation and finding definitions all happen in Hammerspoon:

| Key                    | Action                                      |
|------------------------+---------------------------------------------|
| =, e e=                | evaluate the expression before point        |
| =, e f=                | evaluate the top-level form                 |
| =, e r=                | evaluate the region                         |
| =, e b=                | evaluate the buffer                         |
| =, d d=                | documentation                               |
| =, f d=                | find the definition (xref)                  |
| =, '=                  | switch to the REPL (starting one if needed) |
| =, r=                  | reload a module                             |
| =M-x hammerspoon-repl= | a Hammerspoon REPL from anywhere            |

The plain =fennel-repl= works with the script as well.

Each REPL has an environment of its own over Hammerspoon's globals: it reads them,
=global= sets them, and its locals, =print= and =io.write= stay its own. Saving a
config file reloads Hammerspoon, which ends its REPLs. It leaves a marker by each
socket as it goes; the script waits on it, and once reloaded Hammerspoon opens a
fresh REPL on the same socket, replaying the Proto REPL's protocol upgrade, so the
editor's session carries on (locals don't survive). =,exit= or killing the REPL
buffer ends the script and closes the socket. Interrupting doesn't work: Hammerspoon
can't be stopped midway through an expression.

** Time zone converter (=Convert Time= in the launcher)

=timeconvert.fnl= converts a date and time between time zones in two steps. First,
=lib/read-date.fnl= reads the date and time like =org-time-stamp=, with evil keys:
three months of the Emacs calendar above =Convert: <2026-11-20 Fri 16:05 EST>=,
starting at the current time. In normal state (=<N>= in the mode line) the keys move
the date and time; a count such as =3= repeats the next one.

| Key                         | Normal state                     |
|-----------------------------+----------------------------------|
| =h= / =l=                   | a day back / forward             |
| =j= / =k=                   | a week forward / back (as drawn) |
| =s-h=, =s-k= / =s-j=, =s-l= | a month back / forward           |
| =H=, =J= / =K=, =L=         | a year back / forward            |
| =M-h=, =M-j= / =M-k=, =M-l= | an hour back / forward           |
| =M-H=, =M-J= / =M-K=, =M-L= | 30 minutes back / forward        |
| =C-h=, =C-j= / =C-k=, =C-l= | a minute back / forward          |
| =.=                         | today                            |
| =i=, =a=, =s-v=             | insert state: type (or paste)    |
| =RET=                       | accept                           |
| =ESC=                       | quit                             |

In insert state (=<I>=), type the date, time or zone; the prompt shows how it reads
the input, e.g. =12/25 16:00 EST= => =<2026-12-25 Fri 16:00 EST>=, and the calendar
shades the date. =ESC= applies it and returns to normal state; =RET= accepts it.
Input it cannot read is shown after the date.

| Input                                             | Reads as                               |
|---------------------------------------------------+----------------------------------------|
| =16:00=, =4pm=, =4:30 p.m.=, =noon=               | the time; otherwise the picker's       |
| =2026-12-25=, =12/25=, =12/25/27=, =25.12.=       | the date; otherwise the picker's       |
| =dec 25=, =25 December 2027=, =march=             | the date; without a year, the next one |
| =25=                                              | that day of the picker's month         |
| =fri=, =today=, =tomorrow=, =now=                 | the next Friday (or today), …          |
| =+2d=, =+1w=, =-1m=, =+1y=, =+2tue=, =-fri=       | relative to today, like org            |
| =++3d=                                            | relative to the picker's date          |
| =EST=, =CET=, =Seoul=, =Germany=, =Europe/Berlin= | the time zone; otherwise the picker's  |

An abbreviation names a region, not a fixed offset: =EST= in July reads as New York
time (EDT). A zone alone (=Seoul=) is the current time there, or once you have
moved the picker, its date and time there.

Then pick the zone to convert to: recently used ones first, then the local zone, the
world clock's cities, common zones and all of =zone.tab=, each with the converted time.
Type a city, country, zone or abbreviation. =RET= shows the result in the echo area
and copies it, e.g. =2026-12-25 Fri 22:00 CET=.

Times come from the system's time zone database (=lib/tz.fnl= reads
=/var/db/timezone/zoneinfo=), past 2037 by each zone's DST rule.

** Media (=Cmd-SPC m=)

=media.fnl= sends the keyboard's media keys, so these control whatever macOS shows
in Now Playing: Music, a browser tab, any mpv (EMMS's and the radio's too), and so on.

| Key       | Action                                                            |
|-----------+-------------------------------------------------------------------|
| =s=       | play or pause                                                     |
| =h= / =l= | previous / next track (repeatable)                                |
| =j= / =k= | system volume down / up (repeatable)                              |
| =m=       | mute or unmute the system volume                                  |
| =n=       | show or hide macOS's Now Playing (art, title, position, controls) |
| =a=       | open mpv                                                          |

=n= presses Control Center's Now Playing menu bar item (Control Center itself when
Now Playing isn't in the menu bar); =n= again or =Esc= closes it. macOS has no seek
key that reaches players (fast-forward and rewind do nothing), so seeking is EMMS's
=,= / =.= below.

=a= (=mpv.fnl=) shows mpv's window, switching to its Space, else starts mpv's idle
window (=--player-operation-mode=pseudo-gui=) to drop files or URLs on. Audio-only
mpvs (=--no-video=, like EMMS's and the radio's) don't count. A full screen Space
holds no other window, so from one, mpv opens on a desktop Space and =a= switches
there.

The launcher's =Play/Pause=, =Next Track=, =Previous Track=, =Now Playing= and
=Open mpv= do the same.

*** EMMS (=Cmd-Shift-, a m e= in Emacs)

EMMS's keys are in Emacs' mode keymap, under the same keys as =SPC a m e= in
=init.el=. =mpv.fnl= drives the mpv that EMMS started through its JSON IPC socket
(=--input-ipc-server=): play, pause and tracks go through EMMS (=emms-pause=,
=emms-next=, =emms-previous=, which needs the Emacs server, see Caveats), so its
playlist and paused state stay in sync; seeking, volume and mute go to mpv directly.
The echo area shows the result; seeking shows the new position, or updates the HUD if
it is open.

| Key                  | Action                                                    |
|----------------------+-----------------------------------------------------------|
| =e=                  | EMMS's playlist (=emms=)                                  |
| =s=                  | play or pause                                             |
| =h= / =l=, =p= / =n= | previous / next track (repeatable), then show the HUD     |
| =,= / =.=            | seek back / forward 10 seconds (repeatable)               |
| =<= / =>=            | seek back / forward 1 minute (repeatable)                 |
| =j= / =k=            | mpv's volume down / up by 5 (repeatable)                  |
| =m=                  | mute or unmute mpv                                        |
| =i=                  | show or hide the Now Playing HUD                          |
| =d= / =f= / =u=      | play a directory, file or URL (Emacs prompts)             |

ELispMachine's =init.el= also makes EMMS follow the media keys (=Cmd-SPC m=, the
keyboard, headphones, Control Center): mpv's play/pause and next/previous keys
can't reach EMMS's playlist by themselves, so it watches mpv's =pause= property
and binds mpv's =NEXT= / =PREV= keys to =emms-next= / =emms-previous=.

The Now Playing HUD (=now-playing.fnl=) shows the album art, title, artist, album,
position and a progress bar in the top-right corner. It updates every second, hides
after 8 seconds, and lets clicks through. The art is the file's embedded cover
(extracted with ffmpeg), else an image in its folder named =cover=, =folder= or
=front=, or the folder's only image if it holds an album (two or more tracks), cached as a PNG in the temporary directory. The files are read by a
background process, so Hammerspoon never waits on them; music on an external drive
needs Hammerspoon to be allowed to access removable volumes (System Settings ›
Privacy & Security › Files and Folders).

** Notifications (=Cmd-SPC n=)

=notifications.fnl= drives Notification Center through its accessibility tree. The
/current/ notification is the one peeking in at the top right: the topmost banner,
else the topmost alert (alerts stay until dismissed).

| Key | Action                                                                     |
|-----+----------------------------------------------------------------------------|
| =n= | show or hide Notification Center (as clicking the menu bar clock)          |
| =b= | bury the current notification: swipe it away, keeping it in the center     |
| =x= | clear the current notification, removing it from Notification Center too   |
| =c= | clear all notifications (asks first)                                       |

=b= and =x= are repeatable, for several notifications in a row; both say so when no
notification is on screen, or when Notification Center is open. Notifications have no
accessibility action to swipe them away and macOS ignores synthetic trackpad swipes,
so =b= drags the notification off to the right with synthetic mouse events and puts
the pointer back; the pointer visibly jumps for a fraction of a second. =x= uses the
notification's own =Close= action. =c= opens Notification Center if needed, picks
=Clear All Notifications= from its =Clear Notifications…= menu, and closes it again.

** Radio (=Cmd-SPC a R=)

=radio.fnl= plays internet radio like eradio, under the same keys as =SPC a R= in
=init.el=.

| Key     | Action                                                                  |
|---------+-------------------------------------------------------------------------|
| =a R p= | pick a station and play it                                              |
| =a R s= | stop the radio                                                          |

** Application modes (=Cmd-Shift-,=)

Like Emacs major modes, the frontmost application selects a local keymap.
=Cmd-Shift-,=, the Spacemacs-style local leader, resolves the frontmost app once (by
bundle id) and opens its keymap on top of the leader menu, so the which-key style
popup, =C-g= (back to the leader menu) and =Esc= (cancel) behave as everywhere else.

** Which-key panel

Leader menus are drawn by =lib/which-key.fnl= as an Emacs which-key style panel along
the bottom of the screen with the focused window. Entries are sorted (commands first,
then =+prefix= groups) and laid out column by column, at least six rows high. Keys use
Emacs notation: =s-h= is Cmd-h, =H= is Shift-h, =SPC= is space. Mode commands show
their registry id, e.g. =finder.view.list=. The bottom echo line shows the key path
and keymap, e.g. =SPC w-= or, under the local leader, =s-< v- finder-mode › view=.

Behaviour:
- An app without a mode shows "No mode for …" and binds nothing.
- An undefined key cancels the sequence and is swallowed (not typed into the app).
  Cmd chords such as =Cmd-,= cancel and pass through to the app.
- Switching applications cancels an open mode keymap.
- =C-g= goes back one level, and closes the leader at the top level, as in Emacs.
  =Esc= and =C-[= close it from any level. =SPC= is not bound in menus; in a mode
  keymap it is an undefined key like any other.
- Like Emacs prefixes, there is no idle timeout, except after a repeatable key
  (e.g. EMMS's =a m e n=), which closes the keymap after 2 seconds.
- Menu commands rely on the app's reported menu state, which can be stale for
  about 0.5 s after the app becomes frontmost. A command fired in that window
  may show "Unavailable now".

*** Adding a mode

1. Write the commands, e.g. =podcasts.fnl= returning ={:commands {...}}=. Each
   command is ={:title "..." :fn (fn [app] ...)}= and receives the app resolved
   when the leader was entered. =lib.modes= provides =menu-item= (select a menu
   path; an element may be a list of alternative titles, e.g.
   =["View" ["Show Sidebar" "Hide Sidebar"]]=, for items renamed by state), =menu-item-matching= (select a menu item by Lua
   pattern, for titles that embed the selection such as Copy “a.txt” as Pathname)
   and =press-button= (AXPress a button in the focused window).
2. Declare the mode in =config.fnl= and add it to =:modes=:

#+begin_src fennel
(local podcasts-mode
       {:id :podcasts-mode
        :title :Podcasts
        :bundle-ids [:com.apple.podcasts]
        :commands (. (require :podcasts) :commands)
        :keymap [{:key :p :title :play :command :podcasts.play-pause}
                 {:key :g :title :go          ; prefix: any depth of :items
                  :items [{:key :l :title :library :command :podcasts.library}]}]})
#+end_src

The keymap is the single source of truth for dispatch and help. Commands can be
run without their key sequence, and both can be introspected from the console:

#+begin_src lua
modes = require("lib.modes")
modes["execute-command"]("safari.toolbar.customize")
print(modes["describe-mode"]("safari-mode"))
print(hs.inspect(modes["describe-key"]("safari-mode", {"t", "s"})))
print(hs.inspect(modes["list-commands"]()))
#+end_src
